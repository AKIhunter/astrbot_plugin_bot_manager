# 模型计费配置指南

本指南适用于 Bot Manager 配套服务的「用量 → 配置单价」。
先在 AstrBot 中配置并启用模型 Provider，再在此登记单价与额度。

## 折叠与保存

已有价格和免费额度默认收起，摘要显示模型名、类型、Provider、单价或额度状态。
点击摘要展开或收起；键盘 Tab 定位后按空格也可以操作。
添加价格或额度后，新项自动展开。
保存读取所有配置，包括仍然收起的项；必填项不完整时会先展开对应项并定位输入框。
历史价格版本只供查看，继续用于旧记录的核算。

## 模型从哪里来

| 来源 | 候选规则 |
| --- | --- |
| AstrBot Provider | 读取已启用的对话、多模态、向量、重排、语音合成及语音识别模型 |
| automatic 路由 | 只加入启用、完整配置、未处于检查中、健康检查通过的模型 |
| 现有价格、额度和报表 | 保留已记录模型名，便于继续编辑 |
| 手动输入 | 可以输入还没有调用记录的新模型名 |

配置中存在模型不代表本页面已经测试连通。路由暂不可读时，已配置的直连、
向量和其他 Provider 候选仍保留。接口只返回模型、类型与 Provider 等展示信息，
不会把 API Key 或其他连接凭据返回给页面。

## 向量模型示例

以 AstrBot 百炼 Provider `dashscope_embedding`、模型 `text-embedding-v4` 为例：

1. 在 AstrBot 中配置 API Key、模型名和向量维度，启用 Provider。
2. 打开「用量 → 配置单价」，点击「添加价格」。
3. 在「模型」中选择或输入 `text-embedding-v4`，离开输入框。
4. 如果只有一个匹配连接，Provider ID 自动填写 `dashscope_embedding`；
   如果存在多个连接，自行填写或选择要计价的 Provider ID。
5. 确定生效时间，填写按官方规则核实的普通输入单价。
   单位为人民币元 / 百万 Token，向量通常只计输入 Token。
6. 缓存输入与输出按供应商规则填写：`0` 表示零价，留空表示待配置。
7. 如有免费 Token 额度，点击「添加额度」，填写同一模型和 Provider。
8. 填写总免费 Token、累计起点、起点前或外部已用 Token、到期时间与备注，保存。
9. 在「用量」中筛选该模型，核对 Token、免费 Token 与已核算金额。

不会自动填入未经核实的百炼价格或免费额度。
供应商未返回 Token 的请求显示用量未知，需要与官方账单核对；
向量维度和文本长度不能代替真实 Token。

## Provider 匹配

价格 Provider ID 可留空，此时匹配同名模型；需要区分不同供应商或连接时填写 ID。
多个 Provider 共用一套价格，可使用「同价 Provider ID」；
模型别名共用价格可使用「同价模型别名」。
免费额度必须指定 Provider ID，以免把不同账户的额度混用。
同名模型匹配多个连接时，页面不会任意替用户选择一个连接。

## 计价与额度边界

- 对话与多模态共用对话类型提示；模型类型提示不会自动推断供应商单价。
- 该窗口按 Token 计价，使用人民币 CNY；DeepSeek 支持标准与优惠时段。
- 免费额度按完整历史记录累计，报表筛选或分页不会重复扣减。
- 外部或未采集用量通过「起点前 / 外部已用 Token」补入。
- 未配置超额价格时，超额金额保持待确认。
- 语音、图片等按秒、图片或调用次数收费，需要对应的计量规则。
- API Key、连接地址和向量维度在 AstrBot 配置，该窗口只管理单价及额度。

## 实现与验证

`service/server-monitor.py` 从 Provider 配置和路由健康列表统一发现模型；
报表与价格窗口使用同一候选来源。`service/panel.html` 使用原生
`details / summary` 实现折叠，使用 `datalist` 保留选择和手动输入能力。
原价格结构、生效时间、历史归档与额度重放逻辑保持兼容。

本次更新已验证 16 项计费、14 项模型及 21 项采集回归，
以及折叠保存、键盘操作、错误字段展开、向量单价和额度、自定义模型、
路由不可用时的候选保留和 390px 窄屏布局。
固定生产事件集和时间只读重放后，原金额、Token、模型汇总与免费额度一致。
保存测试使用隔离接口与临时计费文件。
